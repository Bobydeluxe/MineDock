MINEDOCK — PREMIERS PAS SUR GITHUB
Guide préparé le 3 octobre 2026
Choix : projet public, nom conseillé MineDock.
Dépôt du projet : https://github.com/Bobydeluxe/MineDock
Téléchargements : https://github.com/Bobydeluxe/MineDock/releases/tag/v0.1.0

Ce qui est déjà prêt :
- Le code, les tests, la documentation et le README.
- La licence MIT et les mentions des dépendances.
- Les workflows GitHub de validation et de construction.
- Le fichier .gitignore, qui exclut les données locales et fichiers générés.

Les étapes expliquées dans ce guide :
- Créer un compte GitHub et le connecter.
- Enregistrer le code et l'envoyer dans un dépôt public.
- Proposer les installateurs dans une version téléchargeable.
- Envoyer les futures modifications du projet.

Le compte Bobydeluxe et le dépôt MineDock sont créés, le code est publié
et la préversion Windows v0.1.0 est disponible en téléchargement.
Les étapes de création restent utiles si tu souhaites publier un autre projet.

======================================================================
1. À QUOI SERT GITHUB ?
======================================================================

GitHub héberge le code de ton application et son historique.
Un « dépôt » est l'espace du projet sur GitHub.
Un « commit » est une version enregistrée des modifications.
Un « push » envoie ces versions de ton ordinateur vers GitHub.
Une « release » propose une version de l'application à télécharger.

Le dépôt sera public : les visiteurs pourront consulter et télécharger le code.
La licence MIT leur permet de l'utiliser et de le modifier selon ses conditions.
Tes mondes et tes sauvegardes ne sont pas inclus dans les fichiers à envoyer.

======================================================================
2. CRÉER TON COMPTE — À FAIRE EN PREMIER
======================================================================

1. Ouvre https://github.com/signup dans ton navigateur.
2. Suis le formulaire pour créer ton compte personnel.
3. Choisis un pseudo et conserve tes identifiants pour toi.
4. Confirme ton adresse e-mail avec le message envoyé par GitHub.
5. Si une offre payante apparaît, le compte gratuit suffit pour commencer.

La création du compte et la vérification de l'e-mail doivent être faites par toi.
Il n'est pas nécessaire de transmettre ton mot de passe à Codex.
Une fois le compte créé, donne seulement ton pseudo à Codex pour la suite.

Documentation officielle :
https://docs.github.com/en/account-and-profile/how-tos/account-management/creating-an-account-on-github

======================================================================
3. SI TU VEUX QUE CODEX T'AIDE À PUBLIER
======================================================================

Une intégration GitHub a été proposée dans cette conversation.
Après avoir créé ton compte, tu peux l'installer et autoriser la connexion
à ton compte GitHub depuis l'interface de Codex.

Puis indique dans cette conversation :
« Mon compte est créé, mon pseudo est ..., je veux publier MineDock en public. »
Précise aussi si tu as connecté l'intégration GitHub.

Codex pourra reprendre la préparation et utiliser les outils disponibles.
Une connexion confirmée est nécessaire pour agir sur ton compte ; la simple
proposition d'une intégration ne constitue pas une connexion.

Si tu préfères réaliser les clics toi-même, suis les étapes ci-dessous.
Aucune commande PowerShell n'est nécessaire pour ce parcours.

======================================================================
4. INSTALLER GITHUB DESKTOP
======================================================================

1. Ouvre https://desktop.github.com/.
2. Télécharge la version Windows et lance son installateur.
3. Ouvre GitHub Desktop et connecte-toi à ton compte GitHub.
4. Si l'application demande un nom pour Git, utilise ton pseudo.
5. Pour l'e-mail des commits publics, privilégie l'adresse masquée GitHub
   se terminant par users.noreply.github.com lorsqu'elle est proposée.

GitHub Desktop est l'application qui permet d'envoyer les modifications
sans utiliser la ligne de commande.

Documentation officielle :
https://docs.github.com/en/desktop/installing-and-authenticating-to-github-desktop/installing-github-desktop
https://docs.github.com/en/desktop/configuring-and-customizing-github-desktop/configuring-git-for-github-desktop

======================================================================
5. AJOUTER LE PROJET DÉJÀ EXISTANT
======================================================================

Le dossier du projet se trouve dans :
Documents > ChatGPT > Minecraft Serveur Manager

Il contient notamment README.md, package.json, apps, packages et docs.
Il possède déjà son dossier Git local : il faut ajouter ce projet existant.

Dans GitHub Desktop :
1. Ouvre File > Add local repository.
2. Choisis le dossier Minecraft Serveur Manager indiqué ci-dessus.
3. Valide avec Add repository.
4. La liste des changements doit afficher le code et la documentation.
5. Le dossier node_modules, les mondes, data, dist et release sont exclus.

Ne recrée pas un deuxième projet vide à l'intérieur du dossier existant.
Si GitHub Desktop ne reconnaît pas le projet, demande de l'aide à Codex
avant de déplacer ou de remplacer les fichiers.

Documentation officielle :
https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop?platform=windows

======================================================================
6. ENREGISTRER ET PUBLIER LE CODE
======================================================================

Premier enregistrement dans GitHub Desktop :
- Dans Summary, écris : Première version de MineDock.
- Clique sur le bouton Commit pour enregistrer les fichiers sélectionnés.
- Le nom master ou main désigne la branche principale affichée par l'application.

Publication :
1. Clique sur Publish repository.
2. Nom : MineDock.
3. Description proposée :
   Gestionnaire local de serveurs Minecraft Paper et Vanilla pour Windows.
4. Décoche Keep this code private puisque tu souhaites un dépôt public.
5. Utilise ton compte personnel comme propriétaire.
6. Valide la publication.

Le dépôt public sera accessible à une adresse de la forme :
https://github.com/TON-PSEUDO/MineDock

Le README sera affiché sur la page du projet. Les vérifications automatiques
seront visibles dans l'onglet Actions lorsque GitHub les aura exécutées.
Un résultat local réussi ne garantit pas encore le résultat sur les machines GitHub.

Documentation officielle :
https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-an-existing-project-to-github-using-github-desktop

======================================================================
7. PROPOSER L'APPLICATION EN TÉLÉCHARGEMENT
======================================================================

Le code et les installateurs sont distribués à deux endroits différents.
Les exécutables MineDock dépassent 100 Mio et restent exclus de l'historique Git.
Il faut les joindre à une release, plutôt que les ajouter aux fichiers du dépôt.

Sur la page GitHub du dépôt :
1. Ouvre Releases et crée une nouvelle release.
2. Crée le tag v0.1.0 sur la branche contenant le code publié.
3. Titre : MineDock 0.1.0 bêta — Windows x64.
4. Présente les fonctions et les limites de cette bêta.
5. Joins ces fichiers depuis le dossier release du projet :
   - MineDock-0.1.0-Setup-x64.exe
   - MineDock-0.1.0-Portable-x64.exe
   - SHA256SUMS.txt
6. Marque la version comme préversion/bêta.
7. Enregistre un brouillon pour vérifier les pièces jointes, ou publie
   quand la page et les fichiers sont prêts.

Description prête à adapter :

« Première bêta Windows x64 de MineDock, gestionnaire local de serveurs
Minecraft Paper et Vanilla. Java automatique, console, RCON, joueurs,
configuration, fichiers, sauvegardes, tâches et plugins Modrinth.
Les exécutables sont non signés. La connexion avec un vrai client Minecraft
reste à valider après acceptation personnelle de l'EULA.
Linux/macOS et les fonctions avancées ne sont pas livrés comme validés. »

Les visiteurs pourront ensuite télécharger l'installateur sans compiler le code.
Le workflow de construction présent dans le projet conserve des artefacts
de compilation ; il ne publie pas automatiquement une release publique.

Documentation officielle :
https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository
https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github

======================================================================
8. ENVOYER LES FUTURES MODIFICATIONS
======================================================================

Après une modification du projet :
1. Ouvre GitHub Desktop et sélectionne MineDock.
2. Vérifie la liste des fichiers modifiés.
3. Écris une courte description dans Summary.
4. Enregistre avec Commit.
5. Clique sur Push origin pour envoyer les modifications à GitHub.

Le code publié sera alors actualisé. Les installateurs déjà joints à une release
ne se recompilent pas et ne se remplacent pas tout seuls : une nouvelle version
doit être construite et distribuée séparément.

======================================================================
9. SI QUELQUE CHOSE BLOQUE
======================================================================

- Compte non vérifié : confirme l'e-mail envoyé par GitHub.
- Connexion demandée : reconnecte GitHub Desktop ou l'intégration GitHub.
- Nom MineDock déjà utilisé dans ton compte : indique-le à Codex avant de modifier
  un dépôt existant.
- Fichier trop gros : n'ajoute pas les exécutables au dépôt ; utilise Releases.
- Contrôle rouge dans Actions : donne à Codex le lien du contrôle pour diagnostic.
- Fenêtre ou message incompris : copie le texte du message dans la conversation.

Ne supprime pas le dossier de travail ou le dossier .git pour résoudre un blocage.
Le guide t'accompagne jusqu'à la publication et aux futures mises à jour.
La page du dépôt indiquée au début permet de voir son état actuel.
