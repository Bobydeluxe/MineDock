======================================================================
1. WHAT GITHUB DOES
======================================================================

GitHub hosts your application's source code and history.
A repository is the project's space on GitHub.
A commit is a saved set of changes.
A push sends local commits from your computer to GitHub.
A release provides a downloadable application version.

Your repository is public: visitors can read and download the source.
The MIT license permits use/modification subject to its conditions.
Worlds, backups, secrets, runtimes and generated files are excluded by .gitignore.

6. COMMIT AND PUBLISH SOURCE
======================================================================

MineDock is already published. For a new project:
1. Review selected files and enter a short English Summary.
2. Click Commit to save the selected changes locally.
3. Click Publish repository.
4. Select the owner, name and visibility.
5. For a public repository, clear Keep this code private.
6. Confirm publication.

Suggested MineDock description:
Local Minecraft Paper and Vanilla server manager with six interface languages.

main is the primary branch. The README appears on the repository home page.
Automatic checks appear under Actions. A local passing test does not prove
that GitHub's machines have completed their checks successfully.

Official instructions:
https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-an-existing-project-to-github-using-github-desktop

7. PUBLISH INSTALLERS AS A RELEASE
======================================================================

MineDock executables exceed 100 MiB and are excluded from Git history.
Attach them to a GitHub Release instead of adding them to the source repository.

For the multilingual beta:
1. Open the repository's Releases page and create a new release.
2. Choose a new tag, v0.2.0, targeting the tested commit on main.
3. Title: MineDock 0.2.0 beta — multilingual Windows x64.
4. Describe features, validation and remaining limitations in English.
5. Attach these files from release:
   MineDock-0.2.0-Setup-x64.exe
   MineDock-0.2.0-Portable-x64.exe
   SHA256SUMS.txt
6. Mark it as a pre-release/beta.
7. Review attachments and publish when the release is ready.

Example release description:
"Local Paper/Vanilla manager with automatic Java, console, RCON, players,
configuration, files, backups, schedules and Modrinth plugins. English is the
default, with French, German, Spanish, Portuguese and Italian available.
Executables are unsigned. Real-client gameplay validation remains pending
after personal EULA acceptance. Platform packaging is not gameplay validation."

Visitors can download installers without compiling source code.
The build workflow retains CI artifacts but does not automatically publish
a public release. Preserve previous release tags and assets; distribute a new
version instead of silently replacing an older binary.

Official instructions:
https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository
https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github

======================================================================
9. TROUBLESHOOTING
======================================================================

- Unverified account: confirm the GitHub email.
- Sign-in requested: reconnect GitHub Desktop or the integration personally.
- Repository name already used: inspect the existing repository before changing it.
- File too large: use Releases for executables.
- Red Actions check: give Codex the failing run's link for diagnosis.
- Unclear message: copy its text into the conversation.

Do not delete the working folder or .git to resolve an authentication/check issue.
Use the repository link at the top to see the published project.
