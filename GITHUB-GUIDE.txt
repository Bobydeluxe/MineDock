MINEDOCK — BEGINNER GITHUB GUIDE
Primary project language: English

Your public project: https://github.com/Bobydeluxe/MineDock

1. WHAT GITHUB DOES
GitHub stores the source code and its history. A repository is the project
folder online. A commit records a change. A branch keeps a set of changes
separate while they are being tested. A pull request lets you review and
merge a branch. A release is a downloadable version of the application.

2. USING MINEDOCK WITHOUT PROGRAMMING
Open the repository, then Releases. Read the release notes and choose the
package matching Windows/Linux/macOS and x64/ARM64. You do not need to
download the source ZIP or install Node/pnpm just to use a built package.
An older executable does not gain new features just because source code
has been updated. Unsigned packages are identified in their release notes.

3. FINDING THE CODE AND FEATURE LIST
The Code tab shows project files. README.md explains the application.
MineDock-Features.txt lists implemented features and remaining limits.
docs/validation.md records actual test/build results. docs/roadmap.md lists
remaining prerequisites and future work. Click a file to read it online.

4. CHECKING AUTOMATED TESTS
Open Actions. A green check means that workflow's steps passed. A red cross
means a step failed; open the run and job to read its diagnostics. A build
artifact is a CI output, not automatically a published release. Packaging
success is not proof of Minecraft client gameplay or a valid OS signature.

5. REPORTING A PROBLEM
Open Issues, then New issue. Describe your OS/architecture, MineDock version,
what you did, what happened and the expected result. Include a sanitized
error message. Never publish passwords, RCON secrets, API keys, private
certificates, update signing keys, personal addresses or private worlds.

6. PUBLIC REPOSITORY AND SECRETS
Everyone can see committed source code. Local servers/backups/data and
private signing files are ignored by Git. Keep that protection. CI secrets
are configured in repository Settings > Secrets and variables > Actions;
they do not belong in a text/code file. CurseForge keys are configured
privately in the application. No Windows/Apple certificate is required
for an unsigned local build, but real signing needs the owner's credentials.

7. DEVELOPMENT WHEN YOU WANT TO EDIT THE APP
Install Git, Node 24+ and pnpm 11+, clone this repository and follow
docs/development.md. Work on a branch, run the checks, then create a pull
request. End users can keep using release executables without those tools.

8. RELEASES AND MINECRAFT LICENSING
Only publish tested packages with accurate notes and matching checksums /
signed update metadata. MineDock updates do not update Minecraft servers.
Personally read and accept the Minecraft EULA in the app when required;
automated tests deliberately stop at eula=false and do not consent for you.
