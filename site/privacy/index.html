2. What the application stores locally

  • Server profiles, engine and game versions, local paths, configuration, preferences and scheduled tasks.
  • A local SQLite database, including player usernames/UUIDs, observations, sessions, administrative history and private operator notes.
  • Minecraft world, inventory, statistics, whitelist, operator and ban files; those files and native server logs can contain personal information.
  • Backups, restore previews and safety copies, configuration history, database migration copies and retained trash.
  • Application/error logs, local crash evidence, console output and local process/player-count performance measurements.
  • RCON credentials, cached catalogs/icons/skins, private verified game resources, selected mod/pack resources and downloaded application updates.

These are stored in the app's user-data directory and the server/backup folders you select. MineDock implements no automatic upload of worlds, inventories, SQLite, private notes or backups. A shared folder, OS cloud backup, plugin or deliberate export can move files elsewhere independently. An export is not necessarily anonymous.

3. Network requests and your choices

MineDock makes Internet requests for online features. Each recipient can see your public IP address, requested URL/resource, time and normal connection/HTTP metadata. HTTPS protects transport to the recipient; it does not hide the request from that service. DNS resolvers, proxies and the operating system can also process connection metadata. Provider requests use a product User-Agent, not a unique publisher device ID.

The listed public API/download flows do not sign you into GitHub, Microsoft or Modrinth, and do not send your Minecraft password. RCON authentication is a separate local-server operation. Some requests happen as a result of opening a view; there is no universal offline switch or per-feature network opt-out in 0.5.0. Avoid the relevant online feature or restrict application network access through your OS if required. Existing cache may reduce requests, but does not guarantee none.

4. Analytics, crash reporting and publisher access

The audited MineDock code has no publisher analytics SDK, automatic crash-report upload, advertising identifier, remote persistent device identifier or publisher-operated telemetry endpoint. The local performance screen measures your server processes; it does not send usage statistics to the MineDock publisher.

The publisher receives information you deliberately provide by email or a GitHub issue/report. GitHub issues are public and disclose your account and submitted content. Review and minimize logs before sharing; do not upload complete player files, passwords or private worlds. Third-party APIs may keep their own access/download statistics.

5. Retention, deletion and uninstalling

You control local storage. Removing a server keeps a recovery copy in app-owned trash; backups and an imported external original can remain. Player-edit safety copies, database/configuration backups and incremental objects can survive a change. Removing a record or clearing a cache does not erase all other copies.

Configured backup retention is previewed before deletion. Local metrics have a seven-day maintenance limit. Player detail retrieval prunes ended sessions older than 180 days and caps ended sessions at 20,000 per server; administration history is also capped at 20,000 per server. These are application rules, not promises to purge native logs, notes, original player files or all backups. Application logs rotate around 5 MiB; the console memory buffer holds up to 5,000 lines per server. Other local records can persist until deliberately removed.

On Windows, uninstall a Setup build through Installed apps. For Portable, close MineDock and remove its executable. The Windows uninstaller is configured to retain application data; deleting the program does not delete your worlds, SQLite or chosen storage folders. To remove all data, stop servers, close the app, review independent backups/external originals, then deliberately remove the actual profile and all chosen storage/recovery locations you intend to erase. Deletion is not certified secure erasure, and OS/cloud backups can retain copies.

Art-cache purge removes app-owned cached resources and registrations without deleting the original installed Minecraft client. Browser cookies/storage, provider records and third-party server files have separate deletion controls.

6. Security measures and limits

MineDock validates HTTPS download destinations and redirects, bounds response/archive sizes, compares expected hashes and verifies updater metadata using a pinned Ed25519 key. It uses renderer isolation/sandboxing, typed IPC, path checks and guarded inventory writes with verified backups. These controls do not guarantee error-free software or trustworthy third-party programs.

Stored RCON secrets use Electron OS protection where available, with a local AES-256-GCM key fallback. The full SQLite database/world files are not encrypted by MineDock, and the native server requires plaintext RCON configuration. Local redaction is best effort; other server/plugin secrets can remain in files or shared backups. Protect your OS account, filesystem and backup locations. Current unsigned Windows/macOS packages and signed updater metadata are different matters; see Code signing policy.

7. Website hosting, cookies and external providers

The prepared GitHub Pages site serves static HTML/CSS, same-site images and system fonts. It has no account, contact form, ad, embedded video, analytics script, tracking pixel or source-set cookie/browser storage. No Google Analytics or Tag Manager is installed.

GitHub states that Pages visitor IP addresses are logged for security, including signed-out visitors. The publisher has no visitor-log dashboard in this static export. GitHub's own notice explains its purposes, retention criteria, rights contacts and international processing; no exact Pages log lifetime or publisher deletion power over GitHub logs is claimed. Cookies/headers on the actual Pages host remain to be checked after deployment; local source inspection cannot establish production cookie behavior.

External services are contacted only as described above or when following links. Relevant provider information: GitHub, Microsoft/Minecraft, Modrinth, Hangar, PaperMC's linked notice, Eclipse/Adoptium, and Google/Gmail.

Official projects also include Purpur, Fabric, Forge, NeoForge, Geyser and mcstatus.io. A current API-specific privacy notice has not been established for each smaller provider; no common retention/location guarantee or unrelated privacy notice is assigned to them.

Providers and the designated Gmail service can process information internationally, including outside your country/EEA, under their own arrangements. Consult their current notices for applicable transfers and safeguards. MineDock does not promise exclusively EU storage or invent a processor agreement. Search Console ownership/indexing is not established; planned static verification does not add visitor analytics.
