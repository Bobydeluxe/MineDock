MINEDOCK — COMPLETE FEATURE LIST
Source version: 0.3.1 beta (UI revision; not yet published)
Updated: 4 October 2026
Repository: https://github.com/Bobydeluxe/MineDock

English is the primary project language and default application language.
Implemented means connected to the real backend with relevant automated tests.
It does not mean every release has had a real Minecraft gameplay session.
See docs/validation.md for exact native build/test results and remaining limits.
Older 0.2.0 release downloads do not include the 0.3.0 extensions.

======================================================================
1. DESKTOP APPLICATION — IMPLEMENTED
======================================================================
- Local-first Electron application; no mandatory cloud account.
- Multiple independent Minecraft server profiles; SQLite persistence.
- First-launch wizard: language, theme, folders and machine diagnostics.
- English, French, German, Spanish, Portuguese and Italian available offline.
- Immediate language preview; saved preference survives application restart.
- Translated MineDock dialogs, errors, crash explanations and task descriptions.
- Original Minecraft console output, file contents and external content retained.
- Light, dark and system themes; server status and recent activity.
- Centered native dialogs with body scroll lock, internal scrolling, keyboard
  focus containment/restoration, accessible names and guarded backdrop/Escape.
- Four-step engine/resource/settings/review wizard with original offline engine
  icons, edition selection, collapsed advanced options and port/RAM validation.
- OS/architecture, memory, disk-space, Java and local-network diagnostics.
- Port availability and reservations; native file/folder dialogs and reveal.
- Single application instance; optional sleep prevention while servers run.
- Offline local administration after installation; downloads require Internet.

======================================================================
2. EIGHT SERVER ENGINES — IMPLEMENTED
======================================================================
- Java: Vanilla, Paper, Purpur, Fabric, Forge and NeoForge.
- Bedrock: official Bedrock Dedicated Server and PocketMine-MP.
- Official catalogs, explicit Minecraft versions and pinned release/build IDs.
- Fabric loader/installer selection; Forge and NeoForge loader builds.
- Engine-specific installation, launch, readiness, stop and administration.
- Dedicated Forge/NeoForge installer with captured logs and bounded timeout.
- Modern Forge/NeoForge argument-file launch support.
- Required Java version chosen from server metadata.
- PocketMine PHP version chosen from official release requirements.
- Native Bedrock executable/architecture checks.
- Official hashes verified whenever supplied by upstream.
- Java EULA consent explicitly required; never accepted by automated tests.
- Edition-aware UI; Java heap controls hidden for PHP/native engines.
- Capability checks hide/refuse unsupported mods, plugins, RCON or commands.
- BDS officially supports Windows/Linux x64 only; no macOS/ARM64 fallback.
- Historical BDS releases unavailable when Microsoft no longer lists them.
- ARM64 never silently receives an x64 executable.
- PocketMine upstream support has ended; release number and supported Bedrock
  game version are shown separately. See docs/engines.md.

======================================================================
3. LIFECYCLE, CONSOLE AND METRICS — IMPLEMENTED
======================================================================
- Start, graceful stop, restart, auto-start and optional crash restart.
- Startup/shutdown timeouts; confirmed forced termination.
- Repeated-crash circuit breaker and readable crash explanations.
- Orphan-process checks following an application interruption.
- Streaming console, bounded logs, filtering and command history.
- Supported engine console commands and Java RCON.
- Encrypted RCON credentials; MineDock logs/audit redact secrets.
- CPU and memory from the actual server process, without fake measurements.
- Executable/launch-file and occupied TCP/UDP checks before startup.
- Unresolved recovery blocks affected server launches and mutations.
- Engine-aware properties and structured input validation.
- Stopped-server safety backups before risky changes/version updates.
- Server trash/recovery; removing a managed-original profile keeps its folder.

======================================================================
4. MODS, PLUGINS AND MARKETPLACES — IMPLEMENTED
======================================================================
- Modrinth server plugins and loader-compatible mods.
- Hangar plugins on supported engines.
- CurseForge official API with owner key, encrypted storage and missing-key UI.
- Search, real metadata, selected versions, changelogs and compatibility filters.
- Pinned required dependencies; bounded traversal, cycles/conflicts rejected.
- Distribution restrictions and unavailable download URLs respected.
- Unknown upstream server-side compatibility is explicitly reported as unknown.
- Approved bounded raster icons/cache; SVG refused; cache can be cleared.
- Managed binaries stored in SQLite; manual files listed separately.
- Configs/manual content preserved during installation and updates.
- Explicit update comparison, enable/disable, history and hash-verified rollback.
- Default history: five versions; configurable up to twenty.
- Confirmed uninstall; required dependencies protected from premature removal.
- Safety backup and staged folder exchange before managed mutations.
- Files changed outside MineDock reported rather than silently overwritten.
- Manual datapack/resource/config folders remain visible; no general-purpose
  datapack/resource-pack installer is included.

======================================================================
- Official engine-compatible Geyser/Floodgate plugin/mod distributions.
- Paper/Purpur and currently supported Fabric/NeoForge variants.
- Upstream game-version checks and required Fabric API/ViaVersion dependencies.
- Verified downloads; explicit UDP port and optional Floodgate/authentication.
- IPv4/IPv6 UDP availability and cross-server reservations.
- YAML preserves unrelated settings and Java online-mode.
- Installed/configured status and managed-file integrity checks.

6. EXISTING SERVER IMPORT — IMPLEMENTED
======================================================================
- Native folder selection; read-only preview of engine/version/loader/launch

- Ambiguous metadata editable; launch choice must be explicit.

======================================================================
7. WORLDS — IMPLEMENTED
======================================================================
- Java worlds discovered with associated Nether/End/custom dimensions.
- Bedrock/PocketMine worlds discovered from their actual folders.
- Bounded Java compressed NBT and Bedrock little-endian metadata parsing.
- Exact 64-bit seeds retained as text; actual available names/spawn/game mode/
  timestamps displayed. Missing metadata remains unknown.
- Folder, ZIP and MCWORLD preview/import with edition checks.
- One base world/dimension set per import; original source kept.
- Export, duplicate, rename, select and inactive-world deletion.
- Stopped-server checks, typed confirmation and preventive server backups.
- World-management action refuses active-world deletion.
- Duplicate UUID/stale session-lock handling; persistent world history/recovery.
- No automatic Java/Bedrock conversion.

8. MODPACKS — IMPLEMENTED FOR MODRINTH .MRPACK

- Real format-1 manifests; preview of pinned game/loader versions.

- Actual known mod provenance recorded; unknown provenance remains manual.

11. STORAGE — IMPLEMENTED
======================================================================
- Explicit on-demand scans of actual server files and registered backups.
- Worlds/dimensions, mods, plugins, logs, config and other categories.
- Shared application caches excluded from per-server totals.
- Twenty largest files with relative paths, size, filesystem dates and reveal.
- Ninety saved reports; bounded depth/count/bytes, link exclusion/cancellation.
- Partial/cancelled scans never saved as completed measurements.

======================================================================
12. SCHEDULES — IMPLEMENTED
======================================================================
- Interval, daily and five-field cron expressions.
- Timezone, next-run preview and readable descriptions in six languages.
- Persisted task enable/disable (pause/resume).
- Start, stop, restart, backup and supported command tasks.
- Multiple restart-warning deadlines and custom message text.
- Missed offline tasks are not replayed in a destructive burst.
- Results/errors audited; unsupported engine actions refused.

======================================================================
13. BACKUPS, RESTORE AND RETENTION — IMPLEMENTED
======================================================================
- Streaming ZIP/manifest/SHA-256; manual, scheduled and safety backups.
- Eight engines' launch/runtime/world/modpack metadata preserved.
- Consistent stopped backup; live Java save-off/flush/save-on via RCON.
- Save-on attempted in finally; server stopped safely on failed save recovery.
- Ordinary portable exports scrub secrets; original-import archives stay private.
- Verified native backup export; staged restore, rollback and recovery journal.
- Native engines without safe live save control require stopped backups.
- Count, elapsed-days and GFS policies with timezone.
- GFS defaults: 24 hourly, 7 daily, 4 weekly, 12 monthly representatives.
- Newest existing bucket representative retained; no synthetic missing backups.
- Manual/safety and newest eligible archive protected by default.
- Expiring hash-verified preview lists kept/deleted/unavailable, count and bytes.
- Purge requires exact server name and an extra phrase when manual copies
  are explicitly included. Purging is an explicit action, not unattended deletion.
- Interrupted batches restore pending archives or finish committed cleanup;
  unexpected files remain available for review.

======================================================================
14. RUNTIMES — IMPLEMENTED
======================================================================
- Official managed Temurin Java and required PocketMine PHP.
- Missing managed installs and detected system Java included in runtime list.
- Actual version probes, PHP ZTS and PE/ELF/Mach-O architecture checks.
- Unknown architecture never presumed compatible.
- Verified official repair staged before replacement; previous files preserved
  on failure/cancellation. Required Unix PHP extension paths resolved.
- Active use or unresolved recovery blocks runtime changes.
- Confirmed deletion of managed runtimes; system installations read-only.
- Referenced deletion needs explicit compatible healthy replacement, with
  server references committed together.
- Upstream missing architectures reported unavailable without x64 fallback.

======================================================================
15. OPERATIONS, DOWNLOADS AND RECOVERY — IMPLEMENTED
======================================================================
- Persistent job ID/phase/progress/status/audit and safe cancellation boundaries.
- Shutdown cancels/awaits jobs before SQLite closure.
- Approved HTTPS, bounded redirects/responses and cross-host credential removal.
- Official hashes/sizes, temporary downloads and final atomic replacement.
- Persistent partials with ETag/Last-Modified, Range/If-Range, prefix hash and
  Content-Range checks; clean fallback when safe resumption is unsupported.
- Prepared/original/previous checkpoints and database commit markers.
- Startup rollback or committed cleanup; ambiguous/missing copies need review.
- Verified native review paths; uncertain copies preserved.
- Typed retry/rollback or verified registered safety-backup restore.
- Unresolved exchange/retention cannot be dismissed destructively.
- Sudden power loss or OS installer boundaries may require manual recovery.

16. APPLICATION UPDATES — IMPLEMENTED INFRASTRUCTURE
======================================================================
- MineDock updates separate from Minecraft/server updates.
- Optional startup/periodic automatic checks, disabled by default.
- Manual check/download and explicit install/restart confirmation.
- Embedded publisher Ed25519 public key; private key absent from source/app.
- Signed version/dates/expiry/OS/architecture/package/URL/size/SHA-256 metadata.
- Unsigned/invalid/expired/downgrade/mismatched-architecture releases refused.
- Downloaded installer rehashed immediately before installation.
- Active servers/jobs/unresolved recovery block installation.
- Windows portable replacement preserves prior executable; NSIS opens installer.
- Linux AppImage replacement; deb uses system installer.
- Writable macOS ZIP bundle replacement; dmg uses system installer.
- Persistent installation request/result checked on next startup.
- Publisher CI secret configured separately from OS-signing certificates.
- Public v0.3.0 signed feed verified for all twelve native package targets.
- Real public Windows portable download rechecked against signed size/hash.
- Published 0.3.0 correctly reported no newer version in the feed validation.
- Actual newer-version OS installation/relaunch remains unvalidated.

17. SECURITY, DATABASE AND DISTRIBUTION — IMPLEMENTED
======================================================================
- Electron sandbox/context isolation; renderer has no Node access.
- Narrow typed preload, payload/frame/origin/sender validation, structured errors.
- No production fallback to demo/mock backend.
- Original SQLite migration 1 preserved; append-only migrations 2 through 5.
- WAL checkpoint/database backup before upgrade; persistent feature histories.
- Path/size/archive/link checks; verified native system aliases normalized.
- Encrypted local secrets and redacted logs/audit.
- Server binaries/plugins execute with owner privileges; no Docker isolation.
- Native Windows NSIS/portable, Linux AppImage/deb, macOS dmg/zip.
- Six native CI targets: Windows/Linux/macOS x64 and ARM64.
- Packaged UI/filesystem tests; Linux Xvfb with Electron sandbox enabled.
- Conditional Windows signing with real certificate/password.
- Conditional macOS hardened signing/JIT entitlement and Apple notarization.
- Usable unsigned packages when certificates are missing.
- Owner currently has no Windows/Apple signing certificates.
- Publisher metadata signatures do not imply Authenticode/Apple notarization.
- License and third-party notices included in artifacts.

======================================================================
18. VALIDATION AND REMAINING LIMITS
======================================================================
- Tests cover migration preservation, paths/archives, resumable HTTP, dependency
  conflicts, imports, worlds, file operations, players/storage, schedules,
  runtimes, retention/recovery and signed-update tampering/refusal.
- Twenty-three UI cases include actual Electron/main/preload/SQLite journeys and
  explicit isolated demo scenarios; fixtures never become production data.
- Packaged suite includes actual Electron journeys and native dialog resizing.
- Six-language preference/reload/restart tested.
- Unsaved language/theme edits survive unrelated background snapshot refreshes.
- Opt-in official catalogs, actual Java/PHP probes and content transactions.
- Opt-in real Paper bootstrap uses eula=false; no playable world created.
- Real Minecraft clients/gameplay/crossplay/historical-engine compatibility
  unvalidated without owner consent and clients.
- CurseForge live requests require the missing API key.
- OS signing/notarization require missing certificates/credentials.
- Interactive NSIS/deb/dmg installation, keychain behavior, large-server load,
  disk-full and extended power-loss testing remain separate validation work.
- Exact current build/test outcomes: docs/validation.md.
