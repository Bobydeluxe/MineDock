# MineDock 0.5.0 privacy and network audit

Audited on **10 October 2026**, against released application inputs at `36f7cd12ad8832773377a8b92cd7da3fd616efef` (documentation-only follow-up `8563274cee6bd129f0a820772d4e03a5b2c8f021`). This is a source audit of MineDock's own code, not a packet capture of every dependency, server, plugin or operating-system service. No desktop binaries are changed by this website work.

The proposed combined website/application notice is [the privacy page source](../site/privacy/index.html). Its intended URL is **https://bobydeluxe.github.io/MineDock/privacy/**. It is **not live or ready to submit to SignPath** while the publication gate is closed. The owner supplied `minedockapp@gmail.com` as the public contact and confirmed that private identity disclosure to GitHub has not yet been arranged. No residential information is collected in this repository.

## Local processing and recipients

MineDock has no publisher-operated account, synchronization, analytics, advertising or crash-report upload service in the audited application. Its performance/"analytics" view measures local processes and stores local metrics; it is not audience analytics. Random server, operation and session IDs are local database keys, not transmitted device identifiers. The publisher can receive information a person deliberately emails or posts in GitHub; that is separate from application telemetry.

## Verified network inventory

Every Internet service receives connection metadata such as the source public IP address and requested URL. HTTPS protects transport to that service; it does not conceal requests from the recipient. DNS, proxies/VPNs and the OS can process their own connection metadata. The shared downloader identifies MineDock using a product User-Agent; v0.5.0's general downloader still contains the older literal `MineDock/0.3.1`. The item-specific Modrinth helper identifies `MineDock/0.5.0`. These headers are not a unique device ID. This documentation task does not patch released executables.

No CurseForge integration, publisher cloud, Discord/Slack reporting, AI provider or remote RBAC integration is implemented in these audited flows.

## Storage lifetime and removal

- Windows NSIS explicitly has `deleteAppDataOnUninstall: false`. Use Windows Installed apps to uninstall Setup builds; close and remove a portable executable to remove that program. Neither action is a promise to erase the profile, servers or backups. Other OS package removal also does not remove user-selected storage automatically.
- The data root is `MINEDOCK_DATA_DIR` if set, otherwise Electron's user-data folder plus `data`; the database is `app.db`. Server and backup roots can be chosen independently. Review the app's actual storage paths rather than deleting a guessed directory.
- Removing a server first copies its directory to app-owned `trash`; associated backup files and external original folders can survive removal. Inventory safety copies, configuration/database copies and incremental backup objects can remain. No universal copy garbage collection is implemented.
- Backup retention is operator-configured and previewed. Local process metrics older than seven days are removed by the app's maintenance path. Player detail retrieval prunes ended sessions older than 180 days and limits retained ended sessions to 20,000 per server. Administration records are capped at 20,000 per server; this is not an expiry promise for original Minecraft logs or player files.
- App logs rotate after approximately 5 MiB with a previous `.1` file; the live console buffer keeps up to 5,000 lines per server. Native server/plugin log policies are separate. No fixed lifetime is claimed for all SQLite records, caches or backups. Cache expiration can trigger refresh without immediately deleting cached bytes.
- To remove all local data, stop servers, close MineDock, review independent backups and external/original folders, then deliberately remove the actual profile and chosen storage/copy locations. Logical deletion is not certified secure erasure; filesystem/OS/cloud backups may retain copies.

## Security and responsibility boundaries

The application validates HTTPS download hosts/redirects, bounds responses/archives, compares expected artifact hashes and verifies updater metadata with a pinned Ed25519 key. This does not guarantee every upstream program is safe. Renderer sandbox/context isolation and typed IPC reduce exposure. Secret storage uses available OS protection with a local-key fallback; the SQLite database/worlds are not encrypted as a whole. Server properties and third-party configuration can contain plaintext secrets.

Backups and `.minedock` exports remove the known RCON property in the relevant code paths, but can still contain usernames, UUIDs, inventories, bans, plugin data and other secrets. They are not anonymized archives. User-approved sharing and OS folder synchronization are outside automatic MineDock telemetry.

The server operator controls player processing, lawful bases, notices, access and retention where data protection law applies. The MineDock publisher does not receive those local files simply because someone installs the app. Minecraft servers, JVM/PHP, loaders, plugins/mods, map servers, antivirus and the OS can make independent requests, including player authentication or their own metrics. Audit their policies and settings separately.

## Website, support, legal and SignPath follow-up

The proposed Pages source is static HTML/CSS, same-site images and system fonts: no accounts, forms, JavaScript analytics, trackers, advertising, fingerprinting or source-set cookies/storage. GitHub states that Pages visitor IPs are logged for security ([official Pages documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)). Live host cookies/headers cannot be verified until deployment; local absence is not proof about production.

Provider notices: [GitHub](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement), [Microsoft/Minecraft](https://www.microsoft.com/en-us/privacy/privacystatement), [Modrinth](https://modrinth.com/legal/privacy), [Hangar](https://hangar.papermc.io/privacy/), [PaperMC's linked notice](https://forums.papermc.io/help/privacy-policy/), [Eclipse/Adoptium](https://www.eclipse.org/legal/privacy/), [Google/Gmail](https://policies.google.com/privacy). A current API-specific privacy notice was not established for every smaller provider; the public notice links their official projects and identifies this uncertainty instead of assigning another provider's policy to them. No uniform retention, location or transfer safeguard is invented.

The publisher's contact purpose, recipients, retention criteria, lawful bases and anonymous-publisher arrangement still require approval. GitHub's identity-disclosure route remains unconfirmed. See the [owner steps](website-owner-actions.md), [legal checklist](website-legal-checklist.md) and [code signing policy](code-signing-policy.md). Source facts are completed; this is not GDPR certification or SignPath acceptance. In particular, the released installer does not display this new policy and 0.5.0 has no universal per-feature network opt-out; Foundation review must assess its installation/privacy requirements before any signing integration.
