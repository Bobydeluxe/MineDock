# Extension implementation record

Requested on 4 October 2026. The 0.2.0 baseline has been inspected, including its domain, SQLite schema, services, Electron bridge, React views and existing tests. English remains the default; all six languages must remain complete.

This is a work record, not a declaration of shipped features. A phase is complete only after backend, UI and relevant validation exist.

- [ ] Foundations: engine capabilities, runtime types, appended migrations, structured IPC, persistent operations, safe recovery, HTTP resume and cancellation.
- [ ] Engines: Purpur, Fabric, Forge, NeoForge, Bedrock Dedicated Server and PocketMine-MP; pinned catalogs, installation, launch and engine-aware administration.
- [ ] Content: Modrinth mods/plugins, CurseForge, Hangar, icon cache, version selection, dependency checks, update comparison, rollback and managed uninstall.
- [ ] Crossplay: compatible Geyser/Floodgate variants, UDP configuration and status.
- [ ] Imports: existing servers, Java/Bedrock worlds and .mrpack modpacks, with previews, confirmation and staging.
- [ ] Administration: file rename/move/copy, generic ZIPs, highlighted editor, YAML syntax, persistent players, storage categories and largest files.
- [ ] Automation: pause/resume, daily and cron scheduling, timezone previews, multiple restart warnings and retention previews.
- [ ] Runtimes: health verification, atomic repair, architecture checks and deletion with usage protection.
- [ ] Distribution: secure app updater, conditional Windows signing, macOS hardened signing/notarization, Linux/macOS/arm64 CI and opt-in live checks.
- [ ] Validation: migrations from schema 1, feature/security tests, six UI journeys, lint, types, build, native packaging and truthful English documentation.

External prerequisites: the owner currently has no CurseForge API key and no Windows/Apple signing certificates. Those services must explain missing configuration; unsigned local packaging remains usable. No test may accept Minecraft's EULA for the user. Native OS validation must distinguish configured, built and actually executed/tested results.

## Current work

Foundation services and migration 2 are implemented. The bridge returns structured errors, HTTP partials are persisted with validators, and prepared directory exchanges have a recovery journal. Backups and Java/PHP/runtime operations have cancellation support at safe boundaries. Daily/cron schedules, timezone previews, pause/resume and multiple warning deadlines are connected to the UI. Remaining recovery/cancellation coverage will be completed as imports and content transactions are integrated.

All eight engines are declared. Purpur, Fabric, Forge, NeoForge, BDS and PocketMine have official catalog/install paths and edition/runtime-aware launch paths. Staging and backup manifests preserve launch metadata. The creation UI exposes edition and loader selection and hides Java heap settings for native engines. Native service downloads, gameplay and historical-version coverage still require validation; this phase is not marked complete.

Content providers now use official Modrinth, Hangar and CurseForge APIs. CurseForge keys are encrypted and distribution/download restrictions are honored. The content UI offers explicit versions, dependencies, changelogs, update checks, verified rollback, managed uninstall and separate manual-file listings. A bounded raster icon cache rejects SVG, unsupported hosts and excessive dimensions; it can be cleared in Settings. Binary history is configurable (default five versions). Live CurseForge validation is pending an owner-provided key.

Crossplay has engine-specific Geyser/Floodgate distributions, official metadata, UDP/authentication configuration and an atomic exchange of the prepared server folder. Current Fabric/NeoForge targets are restricted to the supported Geyser Minecraft version. Tests cover preserved worlds/online-mode, generated Java configuration defaults and rollback of invalid YAML/loader requirements. A live isolated plugin transaction verified official Geyser 2.11.3-b1247, Floodgate 2.2.5 build 141 and ViaVersion 5.12.0, their hashes, saved UDP/authentication configuration and an unchanged world sentinel. No Minecraft executable or EULA file was created or launched by this check. Bedrock gameplay and external connectivity have not been tested.

Existing-server import now previews engine/version/entrypoints, worlds and manual content, with editable uncertain values. Copying is the default and leaves the source unchanged. Managing an original requires explicit confirmation, creates a private byte-preserving safety archive before network/RCON changes and retains its folder when the profile is removed. Original-property recovery is authorized only by the recorded native-folder import ticket. Java EULA consent is never inferred; new consent can be recorded only in a prepared copy.

World management discovers Java dimensions as one logical set and Bedrock/PocketMine worlds under worlds/. Bounded read-only NBT parsing preserves exact 64-bit seeds; unknown metadata is reported. Folder/ZIP/MCWORLD import has a preview, edition checks and explicit confirmation. Export, duplicate, rename, select and inactive-world deletion are connected to the UI. Mutations take a safety backup and atomically exchange the prepared server folder; duplicated Bukkit UUIDs and stale session locks are removed. Migration 3 adds world history without changing earlier migrations.

Modrinth .mrpack import now previews pinned Minecraft/loader versions, server-side files, optional downloads and safe override paths. Explicit approval and Minecraft EULA consent precede server creation. The engine, verified mod files and overrides are prepared together; an interrupted or failed installation retains its approved archive and retries the complete pack. Migration 4 records modpack imports and authorized native export destinations. CurseForge modpack imports are not yet implemented.

File management now supports confirmed rename, move and copy, explicit overwrites, staged ZIP extraction and journaled ZIP export. Essential launch paths and managed content are protected. The CodeMirror editor loads on demand, supports syntax highlighting and undo/redo, and rejects invalid JSON or YAML before saving. YAML errors report their line and column without claiming to validate a plugin's configuration semantics. Streamed file copies are cancellable and detect changing sources.

Player observations persist connection counts, session time and locally reported UUIDs/XUIDs. Java operator/whitelist/ban files, Bedrock allowlists/permissions and PocketMine text lists are read in their actual formats. Conflicting identities are reported; account UUIDs are never manufactured. Saved Minecraft statistics and MineDock-observed duration are displayed separately. Ping stays unavailable without server data. Moderation requires exact-name confirmation and uses the engine's supported commands. IP ban addresses are excluded from the UI.

On-demand storage analysis measures server files and registered backup archives by category, keeps ninety reports and displays twenty largest files with relative paths, dates and native folder reveal. Shared application caches are excluded from server totals. Links are excluded, bounded scans support cancellation, and partial scans are never persisted.

Runtime maintenance lists managed Java/PHP runtimes, including missing installations, and detected system Java. Native probes verify actual versions, architectures and PHP ZTS. Repair prepares verified official files before replacing a stopped installation; deletion requires a verified compatible replacement when servers still reference it. Tests cover failed repair, cancellation, architecture headers, active usage and replacement references. Separate isolated native checks verified Temurin Java 21.0.12.1 x64 and the official PocketMine PHP 8.2.30 ZTS x64 on Windows. They executed version probes only. PocketMine upstream has ended support; its release number and supported Minecraft Bedrock version are now distinct in the UI.

Manual recovery exposes validated checkpoint paths and typed confirmation. Restoring a previous original preserves both uncertain current/prepared copies. A verified registered backup can restore a missing full-server original. Server mutation and launch remain blocked while recovery needs attention. Native file and backup exports now use persistent, cancellable atomic replacements, protect active application data and retain an existing selected file after cancellation.

Backup retention supports counts, elapsed days and the newest representatives of existing hourly/daily/weekly/monthly buckets. Manual and safety backups are protected by default, as is the newest eligible archive. Each purge requires a recent verified preview showing count and bytes, exact server confirmation and an additional explicit phrase when manual backups are included. Purging is an explicit user action; unattended deletion is not enabled. Migration 5 journals batch moves and the database commit, so interrupted purges restore pending archives or finish committed cleanup. Unknown files in a recovery directory are preserved.

The application updater verifies raw Ed25519-signed metadata against an embedded publisher key, checks stable versions/dates/repository URLs and matches OS/architecture/package type. Downloads have signed sizes and SHA-256 checks; installation verifies the cached file again. Automatic checks are optional and disabled by default. Native Windows portable replacement passed with inert test files, literal paths and a preserved previous copy; NSIS opens its installer. Linux AppImage and macOS writable-bundle replacements have prepared native helpers, while deb/dmg use the OS installer. Their real native installation behavior still needs validation. A separate publisher key is stored only under ignored data/publisher; it is not an Authenticode or Apple certificate. No trusted production update feed has been published yet.

Distribution scripts use the installed electron-builder v26 schema, optional Windows/Apple certificate aliases, hardened macOS signing with JIT entitlement, and conditional Apple notarization. Certificate values never enter package configuration. The distribution workflow now selects six native x64/arm64 runners and runs packaged Electron filesystem/administration/world/recovery tests, using Xvfb on Linux. These runner jobs are configured but have not yet executed for this extension. Signed updater metadata generation checks that the publisher private key matches the embedded public key; CI requires its own secret configuration.

Intermediate checks on 4 October 2026: 137 unit/integration tests passed, strict TypeScript and ESLint passed and the application build passed. The then-existing eleven UI cases passed; the additional actual Electron recovery/retention journey subsequently passed. Later native file/backup export changes passed 23 targeted tests. The complete expanded suite must be rerun before final validation. Minecraft binaries in isolated UI fixtures are never executed. These results do not certify distribution or native gameplay work.
