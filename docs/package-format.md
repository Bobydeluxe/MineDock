# MineDock portable package, version 1

A `.minedock` file is a ZIP archive with `manifest.json` and a `server/` data directory. It transfers a stopped server's worlds, mod/plugin binaries, resource packs, player lists and reviewed profile. It is not a Java installation or an executable app installer.

The manifest declares `format: "minedock"`, `version: 1`, creation time, source OS, the Minecraft/engine/loader profile, required Java, validated JVM choices, managed content/pack metadata and an inventory of relative paths, byte counts and SHA-256 hashes. Checksums detect corruption; they do not authenticate the sender. Import only trusted packages: mods and plugins execute code with your local permissions.

Default exports omit arbitrary mod/plugin configuration directories, known credential/token/key files, native binaries, shell scripts, logs, caches, locks and temporary files. Known Paper/Purpur YAML configuration has secret-named fields removed. The managed RCON password is always removed, even with the sensitive option. The resource-pack URL and its active selection are cleared by default because URLs may carry access tokens; set a public URL again after importing. World data and player lists contain personal/game data and are included. This is a defined exclusion policy, not a promise to recognize every secret embedded in world or content data.

The export dialog offers an explicit checkbox to include arbitrary mod/plugin configurations. Those files may contain secrets and private settings; keep such a package private. Known credential/key files and the managed RCON password remain excluded. Private MineDock player notes, session history, app credentials and configuration history are never transferred.

Import first extracts into an application-owned preview directory, rejects traversal, symlinks, duplicate/colliding paths, unexpected roots and unsupported launch files, and verifies the whole inventory. Limits are 64 GiB of payload, 100,000 inventory files and 16 MiB of manifest metadata; the shared archive reader also bounds entry counts. The preview shows engine/version, Java requirement, worlds, content count, data size, new ports and adjusted RAM. Previews expire after 30 minutes, with at most five retained; close/startup removes temporary preview copies.

After confirmation and EULA review, MineDock installs the destination's official engine and managed runtime, then commits copied data through the existing recoverable installation transaction. Paths are local to the new profile, occupied ports are changed, RCON gets a fresh secret and RAM is limited for the destination PC. Auto-start stays off. The source server and archive remain unchanged. An Internet connection is required for engine/runtime installation; this format is not a fully offline deployment bundle. A source engine build can differ from the currently available build for that same Minecraft/loader version.

Configuration may contain absolute paths specific to the sender's PC. These arbitrary plugin/mod paths cannot safely be rewritten automatically; inspect them after transfer. Actual cross-OS multiplayer requires native validation on the destination OS. The integration test covers real archive/hash/SQLite/file transactions with controlled engine/runtime responses, and does not claim a Linux/macOS game session.
